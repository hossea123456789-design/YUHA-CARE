# 유하 육아 도구 모음 (YUHA-CARE)

> **개발 인수인계 정본:** [YUHA_CARE_HANDOFF.md](./YUHA_CARE_HANDOFF.md) — 프로젝트 목적, 실제 파일/DB 구조, GitHub Pages 및 Apps Script 배포, UI/UX 판단 이력, 체크리스트·수면 점수 계산, 캐시/동기화, 검증 방법, 미해결 위험과 다음 작업 규칙을 수록합니다.
>
> **향후 유지보수 규칙:** 이 프로젝트의 기능·UI·버그 수정 시 최신 `main` 소스를 확인하고 **[YUHA_CARE_HANDOFF.md](./YUHA_CARE_HANDOFF.md)도 반드시 같은 작업에서 갱신**합니다. 작업 날짜/원인/설계 결정/파일·데이터 영향/QA/커밋/배포 결과까지 변경 로그에 누적합니다.

**실행 링크:** https://hossea123456789-design.github.io/YUHA-CARE/

기존 Google Sheets 데이터를 유지하면서 GitHub Pages에서 체크리스트·수면 기록·PIN 잠금형 아내 회복 기록을 제공하는 웹앱입니다.

## 구성
- 웹 화면: GitHub Pages, `main` 브랜치에서 자동 배포
- DB API: 기존 Google Apps Script (`Code.gs`에서 직접 HtmlService 통신 응답 생성)
- 원본 DB: 기존 Google Sheets `CHECKLIST_DB`, `SLEEP_LOG`, `APP_SETTINGS`; 회복 기록은 별도 `MENTAL_LOG`(비공개 접근 설정 시에만 사용)
- 수면 히트맵: 2차 낮잠 선택 입력, 날짜별 참고 점수(파랑·노랑·분홍), 날짜별 점수 산식과 평가 반영률
- 아내 회복 탭: 별도 PIN 화면 잠금, 7개 0~10점 자가평가, 월간/주간 히트맵, 개인시간·Context·기본욕구 기록, 7일/14일 변화 및 주간 요약. 기기 저장을 기본으로 하며 서버 동기화는 선택 사항.
- 로컬 저장: 수정 즉시 기기에 반영, 체크리스트는 마지막 수정 후 약 2초 유휴 시 묶음 서버 저장, 수면은 필드별 변경 큐·충돌 시 사용자 선택

## 앱을 처음 실행하기 전에 (최초 1회)

1. **Apps Script**: 기존 스프레드시트에 연결된 Apps Script에서 `apps-script/Code.gs` 내용으로 **Code.gs 전체 교체**.
2. **HTML 파일 추가는 필요 없습니다.** 모든 화면 HTML/CSS/JS는 GitHub Pages에 있으며, 통신용 HTML 응답만 Code.gs에서 자동 생성합니다.
3. Apps Script에서 **배포 관리 → 기존 웹앱 수정 → 버전: 새 버전 → 배포**. 이전 `Index`와 `Bridge` 파일은 이 앱에서 사용하지 않으므로 새 배포 후 삭제해도 됩니다.
4. **GitHub 저장소 Settings → Pages → Build and deployment → Source = GitHub Actions** 로 설정합니다. (해당 설정은 GitHub에서 직접 활성화해야 합니다.)
5. Actions 탭에서 `Deploy YUHA CARE`가 완료되면 GitHub Pages 앱을 엽니다.
6. **앱은 `config.js`에 고정된 Apps Script 주소에 자동 연결됩니다.** 기기별로 주소를 입력하지 않습니다.

## 데이터 및 보안 주의
- **DB 데이터는 GitHub에 업로드하지 않았습니다.** 저장소에는 앱 코드만 있습니다.
- `config.js`에는 기존 Apps Script 웹앱의 공개 연결 주소만 저장합니다. 비밀번호·API 키·개인정보는 넣지 마세요.
- 이 저장소는 공개되어 있습니다. 웹앱 이용 권한은 별도로 관리해야 합니다.
- Apps Script의 `ALLOWALL` iframe 설정은 Code.gs가 생성하는 통신 응답에만 적용됩니다. 공개 `/exec` URL 접근 권한은 별도로 점검하세요.
- 기존 Apps Script 주소와 GitHub Pages 주소는 서로 다른 사이트입니다. 앱 화면의 `localStorage`는 사이트별로 분리되므로, 이전 URL에서 **서버에 저장되지 않은 오프라인 수정 내용**은 자동 이관되지 않습니다. 이전 앱에서 먼저 동기화한 뒤 새 주소를 사용하세요.
- HTML이 원격 연결을 필요로 하므로 인터넷 없이 최초 실행하는 경우는 지원하지 않습니다.

## Apps Script 파일 구성

- 필요한 파일: **Code.gs 하나** (최신 버전은 이 저장소의 `apps-script/Code.gs` 참조)
- 필요한 기존 스프레드시트 시트: **CHECKLIST_DB**, **SLEEP_LOG**, **APP_SETTINGS**
- 별도 `Bridge.html`, `Index.html`은 Apps Script에 둘 필요가 없습니다.
- 통신용 내부 HTML 응답은 `Code.gs`의 `serveYuhaBridge_()`에서 동적으로 생성하며, GitHub Pages UI를 서빙하지 않습니다.
- 기존 /exec 배포 주소는 그대로 재사용하되 반드시 **새 버전 배포**해야 합니다.

## 앱 연결 주소 관리

- `config.js`에 고정된 Apps Script `/exec` URL을 모든 기기가 동일하게 사용합니다.
- 주소 변경 시 GitHub `config.js`만 수정하면 됩니다. 기기별로 다시 입력할 필요가 없습니다.
- GitHub 코드는 공개됩니다. Apps Script URL 역시 공개되므로, URL 자체가 인증 수단이라고 가정하지 마세요. 접속 제한 및 수정 권한은 별도로 검토해야 합니다.

## 2차 낮잠 및 수면 평가 v2 (2026-10-20)

- 수면 입력표에는 기존 1차 낮잠 시작·종료가 한 줄로 있고, 해당 날짜 옆의 **작은 `[+]` 버튼**으로 2차 낮잠 시작·종료를 확인·편집합니다. 2차 낮잠 기록이 있어도 **표 행 높이는 늘어나지 않으며**, 작은 팝업의 시각 버튼을 누르면 나머지 수면 필드와 **같은 시간 선택 모달**이 열립니다.
- 수면 데이터는 기존 `SLEEP_LOG` A:K 열을 보존하고 **L열(2차 낮잠 시작) / M열(2차 낮잠 종료)** 을 새로 사용합니다. 새로운 Apps Script는 해당 헤더를 자동 생성하고 I열 낮잠 합계 수식을 두 낮잠을 합산하도록 갱신합니다.
- **필수 서버 변경:** GitHub Pages 배포만으로는 새 열 동기화가 되지 않습니다. 스프레드시트에 연결된 Apps Script 편집기의 `Code.gs`를 이 저장소 `apps-script/Code.gs` 최신본으로 교체하고 **배포 관리 → 기존 웹앱 수정 → 새 버전 배포**해야 합니다. 웹앱 /exec URL은 그대로 유지할 수 있습니다. 구버전 API 감지 시 2차 낮잠 변경은 기기에 보관되고 전송하지 않습니다.
- 점수 평가 항목(가중치, 총 100): **하루 총수면 42 / 밤잠 길이 18 / 입실→취침 12 / 최근 7일 기상·취침 리듬 16 / 낮잠·각성 간격 12**. 마지막 세 항목은 기록이 충분할 때만 평가하며, 관측 가능한 항목 점수로 정규화하여 **평가 반영률**을 함께 나타냅니다. 1회·2회 낮잠 횟수 자체에 감점 없음.
- **공식 권고와 휴리스틱을 구분:** 총수면 권고(AASM)는 1~2세 11~14시간. 다른 평가항목의 구간과 가중치는 공식 임상 기준이 아니라 앱 자체 참고 규칙입니다. 밤중 각성 횟수, 무호흡, 수면 구조, 낮 컨디션을 측정하지 않으므로 점수가 수면의 질이나 질병을 진단하지 않습니다.
- 2차 낮잠을 일부만 입력하거나 두 낮잠 시간이 겹치면 해당 날짜는 기록 미완성으로 표시하고 점수 계산을 보류합니다.
- 기존 체크리스트 데이터 및 1차 낮잠 기록은 그대로 사용합니다.

## 2026-10-21 UI 동작과 인수인계 최신 상태

- 체크리스트 연속 체크는 전체 화면 재렌더링 없이 행·카운터만 변경하며 기기 저장은 즉시, 서버 전송은 **마지막 입력 2초 후 묶음** 처리합니다.
- 우측 상단 **연결됨** 왼쪽은 별도 네모 박스 없는 초소형 동기화 표시입니다. 상태 문구·움직이는 점으로 로딩을 구분하고, 짧은 막대와 숫자를 가까이 배치했으며 완료 시 오른쪽 퍼센트 대신 체크 아이콘이 나타납니다. **막대 %는 서버 실제 전송률이 아닌 시각적 추정치이고 100%는 성공 응답 후에만 표시합니다.**
- 모든 탭에서 고정 헤더 높이를 유지하며, 체크리스트 완료율은 **탭별**로 계산합니다.
- 상세한 결정 근거, 검증 항목, 미해결 리스크 및 세션 간 작업 재개 안내는 **[YUHA_CARE_HANDOFF.md](./YUHA_CARE_HANDOFF.md)**를 참고합니다.

## 2026-10-21 저장 안정성·수면 점수 추가 검토

- 체크리스트는 **마지막 체크 및 리스트 터치 종료 2초 뒤** 서버에 묶음 저장합니다. 화면·기기 캐시는 즉시 변경하며 서버 실패 시 **5~60초 지수 백오프 자동 재시도**와 연결 복구 시 재조회가 있습니다. 브라우저가 기기 저장을 거부하면 더 이상 조용히 저장 완료로 표시하지 않습니다.
- 길게 누르기 드래그가 비정상적으로 붙잡힌 경우 이벤트·포인터 캡처를 정리하고, 동일 서버 데이터 재조회에서 불필요한 체크리스트 화면 재생성을 하지 않도록 합니다.
- 우측 상단 미니 동기화 막대·퍼센트와 **연결됨 텍스트를 동일한 수평 중심선**으로 맞췄습니다.
- 수면 점수에서 **늦은 입실 시각/늦은 실제 입면 시각만으로 추가 감점하지 않습니다.** 총수면·입면 소요시간·규칙성 등의 평가를 유지하고, 12~35개월의 밤 10시 이후 입면은 날짜별 상세 근거에서 연구 한계와 함께 **참고 정보로만** 표시합니다.
- 상세 근거와 사용자 결정 이력: [YUHA_CARE_HANDOFF.md](./YUHA_CARE_HANDOFF.md) §15~16.

## 아내 회복 (Wife Mental Recovery)

기존 수면 히트맵 디자인을 활용한 **본인 중심 회복·소진 추세 기록**입니다. 심리질환 진단이나 가족 구성원의 평가에 사용하지 않습니다.

- **탭 잠금:** 회복 탭을 누르면 숫자 입력패드가 즉시 표시되며, **숫자 4개 입력 즉시 자동 확인**합니다. 별도 '열기' 버튼은 없습니다. 탭을 벗어나면 다시 잠깁니다. PIN은 브라우저 UI 잠금일 뿐, **기기의 localStorage 기록 자체는 암호화되어 있지 않습니다.**
- **7개 평가:** 신체 에너지, 삶의 통제감, 육아 감당 여력, 돌발상황 인내력, 죄책감 없는 휴식, 나를 위한 행동, 나다운 감각. 5단계 선택과 ±0.5 조정.
- **점수:** 일일 평균(7개 항목)과 가중 회복(CONTROL 30%, REST 25%, SELF 25%, ENERGY 10%, TOLERANCE 10%). 미기록/부분기록은 점수에서 제외합니다.
- **히트맵:** 기존 수면 히트맵과 통일된 월간 달력 + 지표별 8행×7열 주간 매트릭스, 주간 요약·트렌드·긍정 신호·월간 그래프.
- **저장:** 최초 상태는 **기기 내부 저장 전용**. Chrome 사이트 데이터 삭제/브라우저 저장 제한 시 기록 소실 가능.
- **비공개 서버 동기화:** GitHub 코드만으로 활성화되지 않습니다. Apps Script에 최신 `apps-script/Code.gs`를 별도 배포하고 **Script Properties의 `YUHA_MENTAL_ACCESS_KEY`에 12자 이상 충분히 복잡한 별도 비공개 암호를 설정**한 다음, 탭의 '기록 저장과 개인정보'에서 명시적으로 연결해야 합니다. 이 서버 암호는 4자리 탭 잠금 PIN과 다릅니다.
- **DB 격리:** 서버 연동 시 `MENTAL_LOG` 시트가 생성됩니다. 기존 체크리스트·수면 자료는 변경하지 않습니다.

**세부 설계 및 인수인계:** [WIFE_MENTAL_RECOVERY_SPEC.md](./WIFE_MENTAL_RECOVERY_SPEC.md) · [YUHA_CARE_HANDOFF.md](./YUHA_CARE_HANDOFF.md)

- 서버 API가 아직 새 버전으로 배포되지 않았다면, 로컬 입력은 가능하지만 **여러 기기에서 기록이 동기화되지 않습니다.**
- 모든 후속 수정 시 **두 인수인계 문서와 필요한 소스 파일을 함께 갱신**하세요.

## 아내 회복 동기화 상태 안내 (2026-10-21)

- 연결된 원본 Google Sheets 문서에 **`MENTAL_LOG` 전용 시트(A:기준일/B:기록 JSON/C:최종 수정)를 생성**했고, 기존 체크리스트·수면 데이터는 그대로 보존했습니다. 생성 직후에는 헤더만 존재하며 개인 회복 기록은 아직 서버로 전송되지 않았습니다.
- **실제 동기화의 필수 조건:** 바인딩된 Apps Script 편집기의 `Code.gs`를 이 저장소의 최신 `apps-script/Code.gs`로 교체하고 기존 웹앱을 **새 버전으로 배포**해야 합니다. Apps Script 프로젝트 설정의 Script Properties에 `YUHA_MENTAL_ACCESS_KEY`(12자 이상 강력한 별도 암호)를 비공개로 설정해야 합니다.
- 회복 탭의 **기록 저장과 개인정보 → 비공개 접근 암호 → 연결**에서 위 암호를 입력하면, 해당 기기에서 보관하던 미동기화 변경사항은 `MENTAL_LOG`에 저장을 시도합니다. 성공 상태는 **'비공개 동기화 연결됨'** 입니다. 서버 배포와 키 설정 여부가 확인되기 전에는 완료 상태가 아닙니다.
- 한번 정상 인증한 뒤에는 **현재 브라우저 탭 세션에서** 다른 앱 탭으로 이동했다가 돌아와 PIN을 풀어도 자동으로 서버 재연결합니다. 브라우저 탭을 닫으면 이 인증 정보는 없어지며 다음 방문에는 재입력이 필요합니다. PIN은 서버 암호와 다릅니다.

- 조사 결과, 실제 `유하 육아 도구 모음` Google Sheets의 `SLEEP_LOG`에는 **2026-10-18 ~ 2026-11-11의 수면 값이 들어 있는 날짜 25일분**이 남아 있음을 읽기 전용으로 확인했다. 과거 2026-10-28의 백업에도 기록이 있다. **2026-11-11 현재 운영 스프레드시트 전체를 별도 Google Sheets 파일에 긴급 복제**해 재검증했다. 백업 파일의 비공개 ID/URL을 공개 GitHub에 넣지 않는다. 이 수치에는 오직 운영 시트의 확인된 기록만 포함하며 다른 기기에만 남은 미동기화 데이터까지 보증하지는 않는다.
- 원인 1: 구 `index.html`의 `fetchSleepMonthFor()`가 응답 `result.records`를 그대로 `sleepMonths[key]` 및 `localStorage`에 대입하므로 **빈/불완전 응답이 이전 기기 캐시를 지울 수 있었음**. 이제 `mergeSleepMonthWithoutErasing()`가 서버/기기 날짜 및 필드를 빈칸 기준으로 **비파괴적으로 병합**, 양쪽에 서로 다른 비공란 값이 있으면 기기 입력을 화면에 보존하며 `sleepRecoveryState` 차이 내역을 남긴다. 데이터 충돌을 자동으로 서버에 쓰거나 임의 해결하지 않는다. 서버/기기 원본을 `yuha_sleep_rescue_20261111_{YYYY-MM}_{device|server}_{original|recent}`에 독립 스냅샷(첫 백업 불변 + 최신 백업)으로 저장하며, 조회·기록 편집 전 데이터 보호를 우선한다.
- 원인 2: 실 운영 스프레드시트의 **N:O 열에는 기존 '2차 낮잠 시작/종료' 제목이 중복 존재**하고 데이터는 비어 있다. 첫 신필드 서버 코드가 N:S를 새 필드로 사용하려고 하면서 `ensureSleepMetaColumns_()`의 기존 제목 보호 검사와 충돌할 수 있었다. 새 수정본의 관찰 필드는 **P:U (16~21열)** 로 옮겨 N:O 및 기존 A:M을 모두 보호한다. P:U는 실제 백업 당시 공란이었다. P:U 제목이 예상 외거나 헤더가 없어도 아래 데이터가 있는 경우에는 서버가 오류로 작업을 중단하게 해 무단 덮어쓰지 않는다. 새로운 서버 `getSleepMonth()`는 A:U에서 조회하고 `metadataSupported=true`/ `schemaVersion=3`을 반환한다. 밤중 깨어 있던 분을 차감하는 H열 수식은 `P열`을 참조한다.
- `index.html` 수면 탭 상단에 **기존 기록 보호·조회 상태**를 표시한다. 월별 서버/기기 기록 날짜 수, 서버 읽기 실패, 서버의 빈 응답, 양쪽 상이한 값이 있으면 단순 미기록이 아니라 조회 실패/차이임을 분명히 밝힌다. **서버 기록 다시 조회** 버튼은 읽기 재시도(기기 캐시 덮어쓰기 금지). **기기 원본 백업(JSON)** 은 수면용 `localStorage` 키만 로컬 파일로 내보내고 원본을 변경하지 않는다. 서버 재조회가 실패하면 토큰을 제거해 다음 재시도를 막지 않도록 한다. 스크립트 브리지 연결 자체가 없을 때도 JS 오류 대신 읽기 실패를 표시한다.
- **운영 주의:** GitHub Pages 코드 반영은 자동이지만, Google Apps Script 웹앱의 배포는 별도이다. **현재 공개 저장소의 수정된 최신 `apps-script/Code.gs`를 기존 Apps Script 프로젝트에 반영하고 기존 웹앱을 새 버전으로 업데이트해야** P:U 열 구조와 원격 읽기가 정상 적용된다. 배포 전에는 브라우저 저장소/캐시 삭제, 초기화, 재설치, '기기 임시기록 버리기' 등을 피해야 한다. 이전 N:S 기반 Code.gs를 배포하지 않는다.
- 검증은 `tests/sleep-data-rescue.test.js`의 빈 응답/부분 응답/서버·기기 불일치/실 시트 중복 N:O 헤더 보호, `tests/sleep-context-sync.test.js` 구서버 안전 병합, XML·월별 통계·기존 앱 테스트 및 GitHub Pages 배포를 통해 수행한다. **실제 사용자 휴대폰의 캐시 내용과 서버 Apps Script 배포 상태를 원격으로 확인했다고 주장하지 않는다.**


## 2026-11-11 최신 확인 — 수면 데이터 보호, XML 신규 지표 및 제작 인계

- **운영 자료 보존:** 실제 운영 원본과 11월 11일 긴급 백업을 읽기 전용 비교한 결과, 수면 시각을 입력했던 기존 25일분에서 핵심 시각 데이터 누락 0건·기존 비공란 값 변경 0건을 확인했습니다. 운영 P:U 새 관찰 지표가 기록된 날짜는 8일입니다. 이는 다른 브라우저에만 있는 미동기화 기록까지 완전 복구했다는 뜻은 아닙니다.
- **앱 기록 보호:** 서버의 빈 월별 응답·부분 데이터로 기기의 기존 입력을 통째로 덮어쓰지 않도록 비파괴 병합합니다. 원본 분리 스냅샷과 '서버 기록 다시 조회'·'기기 원본 백업(JSON)'을 제공합니다. 오류가 나더라도 캐시·사이트 데이터를 지우거나 원본을 초기화하지 마세요.
- **신규 수면 관찰 지표 XML 출력:** 기존 침대 입실·실제 잠든 시각·기상·1차/2차 낮잠 기록과 함께 여섯 항목이 출력됩니다. `nightWakings`(밤중 각성 횟수, 회), `nightAwakeMinutes`(총 깨어 있던 시간, 분), `napSource`(낮잠 시간 출처), `onsetState`(잠들기 전 편안함·보챔·지속 울음), `specialFlags`(여행·질병·특별 일정, 복수 선택), `morningCondition`(아침 컨디션)입니다.
- **원본 + 한글 해설:** 기존 XML의 `serverVersion`, `deviceVersion`, `pendingChanges`, `conflictVersions` 원본을 유지하면서 수면 날짜별 `sleepObservations`를 추가했습니다. 그 안의 `version source`는 서버/기기/전송 대기/서버 충돌값/기기 충돌값을 구분합니다. 각 지표는 `raw` 속성의 원래 값과 한글 의미를 함께 기록하며, 미입력은 `recorded=false`, 실제 0회·0분은 `recorded=true`로 표시합니다. 기존 전체·특정 월·기간 지정 옵션과 날짜 필터가 그대로 적용됩니다.
- **자동 테스트:** `tests/history-export.test.js`에서 여섯 지표·한글 표기·모든 원본 출처·다중 여행/질병 플래그·0과 미기록·기간 밖 정보 제거를 확인하도록 추가했습니다. Pages CI에는 실제 수면 XML 파일을 Python ElementTree로 파싱하는 단계도 추가했습니다. `index.html`은 이전에 숫자 0을 빈 값으로 바꿀 수 있던 로컬 추출 변환을 교정하고 새로운 `history-export.js` 캐시 버전을 사용합니다.
- **남은 검증:** 최신 GitHub Actions 및 Pages 배포 결과, 운영 Apps Script `/exec`의 `schemaVersion=3` 여부, 실사용 기기 2대의 교차 동기화·XML 다운로드, H열 밤중 각성 시간 차감의 실데이터 검증은 독립적으로 확인해야 합니다. 현행 운영 시트의 기존 H열 수식은 아직 P열 각성분 참조가 없었으며 P열 각성분이 실제 입력된 행도 없었습니다.

## 2026-11-12 아내 회복 대표 점수 통합

- 기존 7개 자기보고 지표에 **하루 체감 수월도**(`scores.ease`, 0~10점/0.5 단위)를 추가했습니다. 질문은 '오늘 하루 육아·일·가사 등을 실제로 얼마나 수월하게 보낼 수 있었나요?'입니다. 개인시간·휴식·육아 부담에 대한 당일의 실제 체감을 별도로 기록할 수 있습니다.
- 화면의 **종합점수는 하나만** 표시합니다. 과거 7개 지표의 평균 × 70% + 실제 입력한 수월도 × 30%를 100점 기준으로 보여줍니다. 기존 '가중 회복' 별도 점수 카드는 제거했습니다. 월별 그래프 역시 종합점수 하나를 표시하고, 7일 평균·전주 대비는 같은 점수의 기간별 변화입니다.
- 과거 7항목 기록은 **기존 점수가 그대로 유지**됩니다. 새 지표가 미입력인 경우 기존 7개 평균을 표시하고 '수월도 미입력'을 알립니다. `ease=0`인 실제 입력은 미입력과 구분하며, 기존 7항목 자체가 불완전하면 대표 점수도 계산하지 않습니다. 구산식과 신산식이 섞인 기간의 추세는 참고용입니다.
- `MENTAL_LOG` 시트의 JSON 안에 새 필드를 보관하며 열 추가·기존 기록 일괄 변경은 없습니다. **새 `apps-script/Code.gs`의 `getMentalMonth.schemaVersion=7`이 필요**합니다. Apps Script 서버 v6가 실행 중일 때는 신규 수월도 입력을 그 기기의 pending에 안전하게 보관하고 서버가 신규 필드를 버리지 못하도록 동기화를 보류합니다. **GitHub Pages 배포만으로 서버의 v7 배포가 완료되지 않습니다.**
- 아내 회복 XML 기록 추출에도 `score.ease`가 원본·서버·기기·미동기화 버전별로 포함됩니다. 다른 점수나 메모·편지 원본 및 저장소 키는 바꾸지 않습니다. 세부 변경 내용과 실제 검증 수준은 [인수인계서 §50](./YUHA_CARE_HANDOFF.md) 및 [아내 회복 세부 명세 §23](./WIFE_MENTAL_RECOVERY_SPEC.md)을 참조하세요.
